00 · Start Here

This is a self-contained course, not a reference manual. It is written for someone who wants to become a network engineer and has no idea where to start.

What this book is

  • A curriculum, ordered so that nothing depends on a concept you have not seen yet.
  • A field guide. Every chapter ends with "what breaks" and "how to prove it".
  • Vendor-neutral first. Cisco syntax appears as an example, but the ideas are the same on Juniper, Arista, FRR, or a Linux box.

What this book is not

  • Not a certification dump. Certifications come after understanding, not instead of it.
  • Not a list of commands. Commands change; the model in your head does not.

How to read it

Use three passes per chapter. Do not skip the third one — it is where learning happens.

Pass What you do Time
1. Read Read the chapter once, without stopping to memorise 20 min
2. Draw Close the book and draw the diagram or the flow from memory 10 min
3. Explain Explain it out loud, as if to a friend who knows nothing 10 min

If step 3 is hard, you did not understand it yet. Re-read only the part that failed.

The five questions to ask about any technology

  1. What problem does it solve? (If you cannot answer, it is trivia.)
  2. What does it look like on the wire? (Bytes, headers, ports.)
  3. What does it look like in the config? (Where do I turn it on?)
  4. What does it look like when it breaks? (Symptom -> cause.)
  5. How do I prove it works? (Which command, which capture.)

Every chapter in this book answers all five.

What you need

  • A computer with a browser and a terminal.
  • Network Lab, the browser-based simulator linked in the page toolbar, for guided switching and routing practice.
  • WSL2 + containerlab + netlab for real routing labs with FRR.
  • Wireshark, free.
  • A notebook. Physical is better. Draw topologies by hand.

A network engineer is not someone who memorised commands. It is someone who can predict what the packets will do, and prove it.

01 · What Networking Really Is

Strip away the marketing and a network is three things: hosts, links, and rules.

The smallest possible network

Two computers and one cable.

[ PC-A ]====================[ PC-B ]
  192.168.1.10              192.168.1.20

For A to send a file to B, four things must be true:

  1. A must know B's address (IP address).
  2. A must know how to reach it (same subnet -> send directly; different -> send to a router).
  3. A must know B's hardware address (MAC address, found with ARP).
  4. Both must agree on the rules (Ethernet framing, IP, TCP or UDP, ports).

Everything else in networking is a variation of these four problems at a larger scale.

Why layers exist

Imagine writing one program that handles: the electrical signal, the cable type, the addressing scheme, retransmission, encryption, and the file format. Now imagine changing Wi-Fi and having to rewrite the file format code.

Layers let each part change independently. Wi-Fi replaces Ethernet without changing TCP. IPv6 replaces IPv4 without changing HTTP. This is the single most important idea in networking.

The cast of characters

Term Meaning Example
Host / endpoint A device with an IP that sends or receives laptop, server, phone, router interface
Link The physical or logical connection between two devices copper cable, fiber, Wi-Fi, a tunnel
Node Any device on the network switch, router, firewall, host
Packet A unit of data with headers an IP packet
Frame A packet wrapped in a Layer-2 header an Ethernet frame
Segment A TCP/UDP unit TCP segment
Protocol An agreed set of rules TCP, OSPF, DNS

LAN, WAN, and the Internet

  • LAN (Local Area Network) — one administrative domain, usually one building or floor. High speed, low latency, you control it.
  • WAN (Wide Area Network) — connects sites over a provider's infrastructure. Lower speed relative to cost, higher latency, you do not control the middle.
  • The Internet — the WAN of WANs. A network of networks that agree to exchange routes using BGP.

A network engineer usually owns the LAN edge, the WAN edge, and the policy between them.

Circuit switching vs packet switching

Old telephone networks reserved a path for the whole call. If you were not talking, the capacity was still reserved and wasted.

The Internet does not reserve anything. It chops data into packets and lets each packet find its own way. This is why:

  • links can be shared by thousands of users
  • a failed link can be routed around
  • but quality is not guaranteed — hence QoS, buffers, and congestion

Bandwidth, latency, throughput, jitter

These four get confused constantly. Learn the difference now.

Term Meaning Analogy
Bandwidth Maximum capacity of a link Width of a highway
Latency Time for one bit to travel How long one car takes
Throughput Actual data delivered per second Cars that arrive per hour
Jitter Variation in latency Uneven traffic flow

A 1 Gbps link with 200 ms latency still feels slow for interactive work. A 100 Mbps link with 2 ms latency feels instant. Latency is usually the real problem.

The bandwidth-delay product

The amount of data "in flight" on a path:

BDP = bandwidth × round-trip time

On a 1 Gbps link with 100 ms RTT, 100 million bits (about 12.5 MB) can be in flight. If the TCP window is smaller than that, you will never fill the link. This is why long, fast paths need window scaling — and why "the link is 1 Gbps but the file transfer is slow" is a real and common problem.

What a network engineer actually does

Activity Share of the job
Designing and documenting 20%
Configuring and changing 25%
Troubleshooting 35%
Automating and improving 20%

Troubleshooting is the biggest slice. That is why this book keeps returning to "what does it look like when it breaks".

Chapter check

  1. Why can Wi-Fi replace Ethernet without changing your browser?
  2. A user says "the internet is slow". Which of the four metrics do you measure first?
  3. You have a 10 Gbps link and a 20 ms RTT. What is the BDP in megabytes?
  4. What are the four things two hosts must agree on to communicate?
Answers
  1. Because layers are independent — the physical/link layer changed, the transport and application layers did not.
  2. Latency first, then throughput, then loss/jitter. Bandwidth is rarely the issue.
  3. 10 Gbps × 0.02 s = 200 Mbit = 25 MB.
  4. Addressing, reachability (routing), hardware address (ARP), and framing rules.

02 · The Models: OSI and TCP/IP

The OSI model is not a protocol. It is a mental checklist that lets you say "this is a Layer 2 problem" and stop guessing.

The two models side by side

   OSI (7 layers)                 TCP/IP (4 layers)
   ------------------             ---------------------
 7 Application  ┐
 6 Presentation ├──────────────►  Application  (HTTP, DNS, SSH, TLS)
 5 Session      ┘
 4 Transport    ──────────────►  Transport    (TCP, UDP, QUIC)
 3 Network      ──────────────►  Internet     (IP, ICMP, OSPF, BGP)
 2 Data Link    ┐
 1 Physical     ┴─────────────►  Link         (Ethernet, Wi-Fi, ARP)

The industry still speaks OSI ("Layer 2 switch", "Layer 3 problem", "Layer 7 firewall"). TCP/IP is what actually runs. Learn OSI to communicate, TCP/IP to build.

What each layer does, and what breaks there

Layer Job Units Typical failure First thing to check
7 Application User-facing protocol Data wrong URL, certificate, app config can you curl it from the host?
6 Presentation Encoding, encryption Data TLS version, cipher mismatch TLS handshake in Wireshark
5 Session Conversation state Data idle timeout, auth session drop logs, timeout settings
4 Transport End-to-end delivery, ports Segment/Datagram firewall blocking port, retransmits ss -tulpn, capture
3 Network Addressing, routing Packet wrong route, ACL, asymmetric path ping, traceroute, routing table
2 Data Link Local delivery, MAC Frame VLAN mismatch, STP loop, duplex switch MAC table, error counters
1 Physical Bits on the medium Bits bad cable, dirty fiber, no light link lights, ethtool, cable test

Rule of thumb: 80% of "network problems" are Layer 1, 2, or a DNS mistake.

Encapsulation

Data moves down the stack on the sender, and up on the receiver.

Sender                              Receiver
HTTP request                        "GET /index.html"
  │                                 ▲
  ▼                                 │
TCP header + data    [TCP|DATA]     │
  │                                 │
  ▼                                 │
IP header            [IP|TCP|DATA]  │
  │                                 │
  ▼                                 │
Ethernet header      [ETH|IP|TCP|DATA|FCS]
  │                                 │
  └──────── wire ───────────────────┘

Each layer adds its own header. At the receiving side, each layer strips its header and hands the payload up. This is why you can capture a single frame and read the entire stack inside it.

MTU and fragmentation

  • MTU (Maximum Transmission Unit) — the largest payload a link can carry. Ethernet default: 1500 bytes.
  • If an IP packet is bigger than the MTU and DF (don't fragment) is set, the router sends back ICMP "fragmentation needed".
  • If DF is not set, the packet is fragmented. Fragmentation is expensive and often breaks firewalls.

Common MTU problems:

Symptom Cause
Ping works, large transfers hang path MTU black hole, ICMP blocked
VPN works for small packets only tunnel overhead reduced MTU, no MSS clamping
SSH connects then freezes MTU/MSS issue on the path

MTU by technology: Ethernet 1500, VLAN tag −4, GRE −24, IPsec −50 to −73, VXLAN −50.

Ports: how one IP carries many conversations

A connection is identified by the 5-tuple:

source IP, source port, destination IP, destination port, protocol

That is how your laptop holds 200 connections to the same server on port 443 and keeps them all separate.

Range Name Notes
0–1023 Well-known HTTP 80, HTTPS 443, SSH 22, DNS 53
1024–49151 Registered vendor-specific services
49152–65535 Ephemeral client-side source ports

See Appendix A for the full port table you actually need.

The troubleshooting ladder

When something is broken, walk the stack. Do not skip.

  1. L1: Is the link up? ip link, ethtool eth0, LED, show interface
  2. L2: Is the MAC reachable? ip neigh, show mac address-table, VLAN correct?
  3. L3: Is there a route? ip route, show ip route, ping, traceroute
  4. L4: Is the port open? ss -tulpn, nc -vz host port, firewall rules
  5. L7: Does the app answer? curl -v, dig, logs

Each step answers a yes/no question. Once a step fails, stop and fix that — do not "try random things" at Layer 7 when the cable is unplugged.

Chapter check

  1. A web request fails with a certificate error. Which layer?
  2. Ping works to an IP but not to a hostname. Which layer, and what do you check first?
  3. Why is the 5-tuple important for NAT and firewalls?
  4. You enable a GRE tunnel and large transfers start hanging. What changed?
Answers
  1. Layer 6/7 (TLS). The path is fine; the certificate chain or time is wrong.
  2. Layer 7 (DNS), not Layer 3. Check resolver config and dig.
  3. Because NAT and stateful firewalls track each conversation by those five fields.
  4. GRE reduced the MTU by 24 bytes; path MTU discovery is failing. Lower the tunnel MTU or clamp MSS.

03 · Ethernet, MAC Addresses, and Switching

Ethernet is Layer 2. It moves frames between devices on the same local network. It does not know about IP, and it does not route.

The Ethernet frame

+---------+---------+---------+----------+-------------+-----+
| Dst MAC | Src MAC |  Type   | Payload  |     FCS     | IFG |
| 6 bytes | 6 bytes | 2 bytes | 46-1500  |   4 bytes   |     |
+---------+---------+---------+----------+-------------+-----+
Field Purpose
Destination MAC Who should receive this frame
Source MAC Who sent it
Type What is inside: 0x0800 = IPv4, 0x86DD = IPv6, 0x8100 = VLAN tag, 0x0806 = ARP
Payload The IP packet
FCS CRC for error detection

Minimum frame: 64 bytes. Maximum: 1518 bytes (1522 with a VLAN tag). Frames outside that range are usually dropped as "runts" or "giants".

MAC addresses

A 48-bit address, written as six hex pairs: 00:1A:2B:3C:4D:5E.

  • First 3 bytes = OUI (manufacturer).
  • Last 3 bytes = assigned by the manufacturer.
  • Unicast — destined for one NIC.
  • Broadcast — FF:FF:FF:FF:FF:FF, every device in the broadcast domain.
  • Multicast — starts with 01:00:5E (IPv4) or 33:33 (IPv6) at the Ethernet level.

MAC addresses are local to the link. They are not routed. When a router forwards a packet to a new network, it writes new source and destination MACs for the next hop.

How a switch works

A switch is a Layer-2 device that learns which MAC lives on which port.

  1. Frame arrives on port 3 from AA:AA:...
  2. Switch records AA:AA -> port 3 in its MAC address table (CAM table).
  3. It looks up the destination MAC:
    • known -> forward out that port only (unicast)
    • unknown -> flood out all ports except the source (unknown unicast flood)
    • broadcast/multicast -> flood
  4. Frames age out of the table after ~300 seconds by default.
Cisco:  show mac address-table
Linux:  bridge fdb show

Collision domains and broadcast domains

  • A collision domain is a set of devices that can collide. Each switch port is its own collision domain. A hub is one big collision domain (avoid hubs).
  • A broadcast domain is a set of devices that receive each other's broadcasts. A switch (without VLANs) is one broadcast domain. A VLAN is a broadcast domain.

This distinction is the reason VLANs exist.

Duplex and speed

Mode Behaviour Symptom when mismatched
Full duplex send and receive at the same time —
Half duplex one direction at a time, uses CSMA/CD collisions, late collisions, slow throughput

Autonegotiation usually works. When it does not — often with old gear, or a hard-coded side — you get a duplex mismatch. Symptom: link is up, ping works, throughput is terrible, FCS/CRC and late-collision counters climb.

Cisco:  show interfaces | include duplex|collision|CRC
Linux:  ethtool eth0

ARP: finding a MAC from an IP

Before A can send a frame to B on the same subnet, it needs B's MAC.

A: "Who has 192.168.1.20? Tell 192.168.1.10"   -> broadcast FF:FF:FF:FF:FF:FF
B: "192.168.1.20 is at BB:BB:BB:BB:BB:BB"      -> unicast back to A

Then A caches the mapping. If the destination is on another subnet, A ARPs for the default gateway, not for the remote host — a detail that trips up a lot of beginners.

Cisco:  show arp
Linux:  ip neigh

Gratuitous ARP — an unsolicited ARP announcement, used when an interface comes up or an IP moves (failover). It is also the basis of ARP spoofing attacks.

Common Layer-2 attacks (and why they matter to you)

Attack How Defence
MAC flooding fill the CAM table so the switch floods everything port security, MAC limits
ARP spoofing answer ARP for the gateway Dynamic ARP Inspection, static entries
VLAN hopping double-tagged frames or trunk negotiation disable DTP, set access ports explicitly, native VLAN ≠ 1
STP takeover become the root bridge BPDU guard, root guard
DHCP starvation exhaust the DHCP pool DHCP snooping, port security

You do not need to be a security engineer, but you must know these exist because they are configured on switches you will touch.

Media types you will meet

Medium Distance Notes
Cat5e 100 m 1 Gbps
Cat6 / 6a 100 m 1 Gbps / 10 Gbps
Multimode fiber (OM3/OM4) 300–550 m 10–100 Gbps, cheap optics
Single-mode fiber kilometres long haul, expensive optics
DAC cable 1–5 m direct attach copper in racks
Wi-Fi varies shared medium, half duplex

Rule: copper inside the rack and to the desk, fiber between buildings and to the core.

  1. A switch receives a frame for a MAC not in its table. What does it do?
  2. Why does a host ARP for the gateway instead of the destination when the destination is remote?

04 · IP Addressing and Subnetting

This is the chapter people fear. It is just binary arithmetic with a shortcut.

The IPv4 address

32 bits, written as four decimal numbers: 192.168.10.25.

192      .168      .10       .25
11000000 .10101000 .00001010 .00011001

An address is split into a network part and a host part by the subnet mask.

IP:    192.168.10.25
Mask:  255.255.255.0    -> /24
       11111111.11111111.11111111.00000000
       |------ network ------|  hosts  |

The first N bits identify the network. The remaining bits identify the host.

CIDR and the block-size trick

Stop converting to binary for every subnet. Use this instead:

Block size = 256 − (mask octet)
Prefix Mask Block size Networks per /24 Usable hosts
/24 255.255.255.0 256 1 254
/25 255.255.255.128 128 2 126
/26 255.255.255.192 64 4 62
/27 255.255.255.224 32 8 30
/28 255.255.255.240 16 16 14
/29 255.255.255.248 8 32 6
/30 255.255.255.252 4 64 2
/31 255.255.255.254 2 128 2 (point-to-point)
/32 255.255.255.255 1 256 1 (host route)

Usable hosts = 2^(host bits) − 2 (network and broadcast are reserved).

Worked example: subnet 192.168.10.0/26

  • Block size: 256 − 192 = 64
  • Networks: .0, .64, .128, .192
  • For .64: network .64, broadcast .127, usable .65–.126
  • Hosts: 2^6 − 2 = 62

So 192.168.10.90 is in the .64 network. One step, no binary.

Second example: 10.1.1.200/27

  • Block size 32, networks: .0 .32 .64 .96 .128 .160 .192 .224
  • .200 falls in .192 → network 10.1.1.192, broadcast 10.1.1.223, usable .193–.222

VLSM: different sizes per subnet

Variable Length Subnet Masking = allocate from largest to smallest need.

Requirement: 100 hosts, 50 hosts, 25 hosts, and two point-to-point links, from 172.16.0.0/24.

Need Prefix Size Allocated
100 hosts /25 128 172.16.0.0/25
50 hosts /26 64 172.16.0.128/26
25 hosts /27 32 172.16.0.192/27
P2P /30 4 172.16.0.224/30
P2P /30 4 172.16.0.228/30
spare — — 172.16.0.232–255

Always allocate largest first. If you start with the /30s you will fragment the space.

Route summarization

A summary is the smallest prefix covering several networks. Convert to binary and take the common leading bits.

172.16.0.0/24   = 10101100.00010000.00000000
172.16.1.0/24   = 10101100.00010000.00000001
172.16.2.0/24   = 10101100.00010000.00000010
172.16.3.0/24   = 10101100.00010000.00000011
                  common: 22 bits      -> 172.16.0.0/22

Summaries reduce routing table size and make the network stable — if a /24 flaps, the summary does not.

Public, private, and special addresses

Range Name Notes
10.0.0.0/8 Private large enterprises
172.16.0.0/12 Private 172.16.0.0 – 172.31.255.255
192.168.0.0/16 Private home and small office
127.0.0.0/8 Loopback 127.0.0.1 = localhost
169.254.0.0/16 Link-local (APIPA) means DHCP failed
0.0.0.0/0 Default route "everything else"
224.0.0.0/4 Multicast OSPF 224.0.0.5, VRRP 224.0.0.18
240.0.0.0/4 Reserved —

169.254.x.x is a diagnostic gift: if a host has it, DHCP did not answer. Say that out loud in an interview and people notice.

Common traps

Trap Reality
"The gateway must be .1" Convention only. Any usable address works.
"A /24 always has 254 hosts" Only if the mask is /24. Check the mask.
Network and broadcast are usable No, except /31 (RFC 3021) and /32.
Overlapping subnets are fine They cause asymmetric routing and NAT chaos. Never overlap.
Renumbering is easy It is the most painful change in networking. Plan space up front.

How to practise

Do 10 problems a day for two weeks. Write the network, broadcast, and usable range for random addresses. Use ipcalc to check yourself:

ipcalc 192.168.10.90/26

Speed comes from repetition, not from reading.

05 · IPv6 Essentials

You cannot avoid IPv6 anymore. Cloud providers hand it out by default, mobile carriers run it, and every certification expects it. Good news: the concepts are the same. Only the notation and a few mechanisms change.

Why IPv6 exists

IPv4 has about 4.3 billion addresses. That ran out. NAT stretched it for decades, but NAT breaks end-to-end connectivity, complicates VoIP and peer-to-peer, and does not scale to billions of devices.

IPv6 has 340 undecillion addresses (2^128). Enough to give every grain of sand an address.

The address format

Eight groups of four hex digits, separated by colons.

2001:0db8:85a3:0000:0000:8a2e:0370:7334

Two compression rules

  1. Drop leading zeros in each group: 0db8 → db8, 0000 → 0.
  2. Replace one run of all-zero groups with :: — only once per address.
2001:0db8:0000:0000:0000:0000:0000:0001
-> 2001:db8::1

The /64 rule

A standard LAN is a /64. That leaves 64 bits for hosts — more than enough for SLAAC. Do not use longer prefixes for LANs; SLAAC requires /64.

Address types

Prefix Type Use
2000::/3 Global unicast routable on the Internet
fe80::/10 Link-local every interface, auto-generated, not routed
fc00::/7 Unique local (ULA) like RFC1918 private space
ff00::/8 Multicast replaces broadcast
::1/128 Loopback localhost
::/0 Default route everything else

There is no broadcast in IPv6. Multicast (and anycast) replace it.

Common multicast addresses:

Address Meaning
ff02::1 all nodes on the link
ff02::2 all routers on the link
ff02::5 OSPFv3 routers
ff02::1:ff00:0/104 solicited-node (used by NDP)

How a host gets an address

Two mechanisms, often both:

1. SLAAC (Stateless Address Autoconfiguration)

  • Host sends a Router Solicitation to ff02::2
  • Router replies with a Router Advertisement containing the /64 prefix
  • Host builds its own address (EUI-64 or privacy extension) and does Duplicate Address Detection

2. DHCPv6

  • Stateful: server assigns addresses (like DHCPv4)
  • Stateless: server only gives DNS and other options; address comes from SLAAC

Most enterprise networks use SLAAC + stateless DHCPv6 or DHCPv6 stateful, depending on the vendor and policy.

NDP replaces ARP

Neighbor Discovery Protocol does what ARP, ICMP redirect, and router discovery did in IPv4.

Message Purpose
Router Solicitation / Advertisement find routers and prefixes
Neighbor Solicitation / Advertisement resolve a link-layer address (ARP replacement)
Duplicate Address Detection is this address already in use?
Redirect better next hop available

NDP runs over ICMPv6. If you block ICMPv6, you break IPv6. This is the number one IPv6 firewall mistake.

What changed from IPv4

IPv4 IPv6
ARP NDP (ICMPv6)

Dual stack and transition

The practical migration is dual stack: run IPv4 and IPv6 on the same interface.

Cisco:  ipv6 unicast-routing
        interface Gi0/1
         ipv6 address 2001:db8:1::1/64
         ipv6 address fe80::1 link-local

Other transition tools you will hear about:

  • NAT64/DNS64 — IPv6-only clients reach IPv4 servers
  • 6to4 / Teredo — legacy tunnels, mostly dead
  • DS-Lite / MAP-T — carrier-grade IPv4-over-IPv6

Common pitfalls

Pitfall Result
Blocking ICMPv6 NDP breaks, nothing works
Using /48 or /56 on a LAN SLAAC breaks
Forgetting link-local for routing protocols OSPFv3/BGP neighbors fail
Assuming no NAT means no firewall Wrong — stateful firewalls still needed
Using :: carelessly in configs valid but usually means "unspecified"

  2. SLAAC builds the interface ID from the lower 64 bits; a longer mask leaves no room.
  3. NDP (Neighbor Solicitation/Advertisement over ICMPv6).
  4. All of them, especially Neighbor Solicitation/Advertisement, Router Advertisement, and Packet Too Big.

06 · Switching in Depth: VLANs, Trunks, STP

Everything here happens at Layer 2, inside one broadcast domain — or between several of them if you configure it right.

VLANs

A VLAN is a logical switch inside the physical switch. Each VLAN is its own broadcast domain, its own MAC table view, and its own subnet (by convention).

Why they exist:

  • Segmentation — voice, data, guest, IoT, management, each isolated
  • Security — a compromised printer cannot sniff HR traffic
  • Flexibility — move a port to another VLAN with one command
  • Scale — 48 ports split into 6 VLANs without 6 switches
Cisco:  vlan 10
        name USERS
        interface Gi0/5
         switchport mode access
         switchport access vlan 10

Access ports and trunk ports

Port type Carries Connected to
Access One VLAN, untagged end devices (PC, printer, AP)
Trunk Many VLANs, tagged another switch, router, hypervisor, firewall

Trunking uses 802.1Q: a 4-byte tag inserted after the source MAC.

+------+------+--------+------+---------+-----+
| Dst  | Src  | 0x8100 | VLAN | Type    | ... |
|      |      |  (TPID)| (12b)|         |     |
+------+------+--------+------+---------+-----+
  • TPID 0x8100 marks the frame as tagged.
  • VLAN ID 12 bits → 1–4094 usable.
  • Frames on the native VLAN are sent untagged on the trunk.

Native VLAN

By default, untagged frames on a trunk belong to VLAN 1. Best practice:

  • Set native VLAN to an unused VLAN on both ends (must match).
  • Never use VLAN 1 for user traffic.
  • Mismatched native VLANs cause silent cross-VLAN leakage — a real security issue.
Cisco:  interface Gi0/1
         switchport mode trunk
         switchport trunk allowed vlan 10,20,30
         switchport trunk native vlan 999

Always set allowed vlan explicitly. Default is all VLANs, which is how a guest VLAN ends up trunked to a place it should not be.

Inter-VLAN routing

Two ways to route between VLANs:

ROAS has a single trunk as a bottleneck. SVI scales in hardware. Learn ROAS to understand the concept, use SVI in real designs.

Spanning Tree Protocol (STP)

Redundant Layer-2 links create loops. Broadcast frames would circulate forever, MAC tables would thrash, and the network would die in seconds. STP prevents this by blocking redundant ports.

How it works

  1. Elect one root bridge — lowest bridge ID (priority + MAC).
  2. Every other switch picks one root port — the lowest-cost path to the root.
  3. Each segment picks one designated port per segment.
  4. All other ports go to blocking (or discarding in RSTP).
        [Root]
        /    \
      [SW2]--[SW3]      one link is blocked

Port states

802.1D (classic) 802.1w (RSTP) Forwards data?
Blocking Discarding no
Listening Discarding no
Learning Learning no (learns MACs)
Forwarding Forwarding yes
Disabled Disabled no

Classic STP takes 30–50 seconds to converge. RSTP takes under a second. Modern networks run RSTP (802.1w) or MSTP (802.1s). Never design with classic STP.

  • Hello 2 s, forward delay 15 s, max age 20 s (classic).
  • Set priority 4096 or 0 on the switch you want as root, and never leave it random.
  • PortFast on access ports to skip listening/learning for end devices.
  • BPDU Guard on access ports to shut them down if a switch is plugged in.
  • Root Guard on ports facing other networks to stop a rogue root.
  • Loop Guard on fiber/trunk links to prevent loops from unidirectional failures.

07 · Routing Fundamentals

Routing is the act of choosing a path for a packet between networks. Everything else — OSPF, BGP, MPLS — is just a way to fill the routing table.

The routing table

Every router keeps a table of destinations and next hops.

Destination        Mask            Next hop        Interface   Metric
0.0.0.0            0.0.0.0         203.0.113.1     Gi0/0       1
10.0.0.0           255.0.0.0       10.1.1.2        Gi0/1       20
192.168.10.0       255.255.255.0   directly connected Gi0/2    0

When a packet arrives, the router:

  1. Looks up the destination in the table.
  2. Picks the most specific match (longest prefix).
  3. If several routes match equally, picks the lowest administrative distance.
  4. Among routes from the same protocol, picks the lowest metric.
  5. Rewrites the Layer-2 header and forwards.

Longest prefix match

Routes:  10.0.0.0/8  -> via A
         10.1.0.0/16 -> via B
Packet to 10.1.2.3  -> matches both -> /16 wins -> via B

Specificity always beats distance. This is why a host route (/32) can override everything.

Administrative distance

Trust ranking between sources of the same route.

Source Cisco AD Meaning
Connected 0 interface is up
Static 1 you configured it
eBGP 20 external BGP
OSPF 110 link state IGP
IS-IS 115 link state IGP
RIP 120 legacy
iBGP 200 internal BGP
Unknown 255 never use

Lower is more trusted. A static route beats OSPF by default — occasionally useful, often a trap when a "temporary" static route is forgotten for two years.

Static routes

ip route 192.168.20.0 255.255.255.0 10.1.1.2      # next hop
ip route 192.168.20.0 255.255.255.0 Gi0/1         # exit interface
ip route 0.0.0.0 0.0.0.0 203.0.113.1              # default route
ip route 10.9.0.0 255.255.0.0 10.1.1.9 200        # floating static, AD 200

Floating static — a backup route with a higher AD. It sits unused until the primary disappears. Classic WAN design trick.

When to use static routes: stub networks, default routes to an ISP, very small sites, backup paths. Not for anything that changes often.

Default route

0.0.0.0/0 matches everything. It is the "rest of the world" entry.

A router with only directly connected routes and a default route is called a stub router. Most branch sites are stubs.

First-hop redundancy (FHRP)

If the default gateway dies, hosts lose connectivity. FHRP gives them a virtual gateway.

Protocol Vendor Notes

VRRP open standard master/backup
GLBP Cisco load balancing across gateways

Hosts point at 192.168.10.1 — the virtual address. If the active router fails, the standby takes over. Preempt is what lets the original router take back over when it returns.

Control plane vs data plane

Plane What it does Examples
Control plane decides the path, builds tables OSPF, BGP, STP, ARP
Data plane forwards packets ASIC, TCAM, FIB
Management plane you talk to the device SSH, SNMP, NETCONF

A router can have a correct control plane and a broken data plane (a bug, an ACL, a hardware fault). This is why "the route is there but traffic does not pass" is a real scenario.

Policy-based routing (brief)

Sometimes you must forward based on source, port, or protocol, not destination.

route-map PBR permit 10

!
interface Gi0/1

Useful for forced inspection or dual-ISP tricks. Use sparingly — it breaks the "routing is destination-based" mental model and confuses everyone later.

Asymmetric routing is a favourite interview topic: the reply takes a different path than the request. Usually fine for routing, fatal for stateful firewalls (they see only half the flow and drop it).

  1. Routes 10.0.0.0/8 via A and 10.1.0.0/16 via B. Packet to 10.1.5.5 goes where?

  4. Why can a stateful firewall break asymmetric routing?
  5. What does 0.0.0.0/0 mean?
Answers
  1. Via B — longest prefix match.
  2. Static, because 1 < 110.
  3. It is a backup path that only appears when the primary (lower AD) route is withdrawn.
  4. The firewall sees the request but not the reply, so it has no session state and drops the return traffic.
  5. The default route: "any destination not matched by a more specific route".

08 · OSPF

OSPF is the most common interior routing protocol in enterprise networks. It is a link-state protocol: every router builds a complete map of the area and computes shortest paths with Dijkstra.

The idea in one paragraph

Each router describes its own links (who I am, who I am connected to, what it costs). Those descriptions are flooded to every router in the area. Every router ends up with the same map (the link-state database). Each router then runs the same algorithm on the same map, so everyone agrees on the best path. No rumours, no counting to infinity.

Neighbors first

Before any routing happens, two routers must become neighbors.

Packet type Purpose
Hello "I am here", keeps the adjacency alive
DBD summary of my database
LSR / LSU / LSAck request, send, acknowledge details

Hello timers must match:

Network type Hello Dead
Broadcast (Ethernet) 10 s 40 s
Point-to-point 10 s 40 s
NBMA 30 s 120 s

If hello/dead, area ID, authentication, or subnet do not match, the adjacency stays down.

Neighbor states

Down -> Init -> 2-Way -> ExStart -> Exchange -> Loading -> Full
  • 2-Way is normal between two non-DR routers on a broadcast segment.
  • Full means databases are synchronized.
  • Stuck in ExStart usually means an MTU mismatch.

DR and BDR

On a broadcast segment with many routers, everyone would form a full adjacency with everyone else (n² adjacencies). Instead, they elect a Designated Router and a Backup DR, and everyone syncs with those two.

  • Election: highest priority wins, then highest router ID.
  • Priority 0 means "never become DR".
  • Non-preemptive: a new router with higher priority does not take over until the DR fails.
Cisco:  show ip ospf neighbor
        show ip ospf interface Gi0/1

Areas

Large flat networks are hard to compute and unstable. OSPF splits them into areas.

  • Area 0 (backbone) — all other areas must connect to it.
  • Normal area — full LSDB for its own area, summaries for the rest.
  • Stub / totally stubby — no external routes (or no summaries either). Smaller tables.
  • NSSA — stub but can import external routes as type 7.
        Area 1 --- Area 0 --- Area 2
                     |
                   ABR

ABR (Area Border Router) connects areas. ASBR injects external routes.

Every area must touch Area 0, directly or through a virtual link (avoid virtual links; they are a design smell).

LSAs you must know

Type Name Origin
1 Router LSA every router, its links
2 Network LSA DR, the broadcast segment
3 Summary LSA ABR, prefixes between areas
4 ASBR Summary ABR, how to reach an ASBR
5 External LSA ASBR, redistributed routes
7 NSSA External ASBR inside an NSSA

Types 1 and 2 build the map. Types 3–5 tell you what is outside.

Cost

cost = reference bandwidth / interface bandwidth

Default reference is 100 Mbps, so a 1 Gbps link costs 1 and a 10 Gbps link also costs 1. That is why modern networks change the reference:

router ospf 1
 auto-cost reference-bandwidth 10000

Or set it manually:

interface Gi0/1
 ip ospf cost 10

Lower cost wins. Cost is cumulative along the path.

Configuration, minimal

router ospf 1
 router-id 1.1.1.1
 network 10.0.0.0 0.0.0.255 area 0
 network 10.1.0.0 0.0.0.255 area 0
 passive-interface Gi0/2
!
interface Gi0/1

Always set an explicit router ID. Passive interfaces on links with no neighbors (users, loopbacks) — a classic hardening step.

Same lab in FRR:

router ospf
 ospf router-id 1.1.1.1

Convergence

When a link fails:

  1. Dead timer expires (40 s by default) or the interface goes down immediately.
  2. The router floods a new LSA.
  3. Every router recomputes SPF.
  4. New routes install.

Tuning for faster convergence: BFD (sub-second failure detection), fast hellos, event-driven SPF. Do not tune timers before you understand them — flapping adjacencies are worse than slow convergence.

Design rules that save you later

  1. One area 0, keep it small and stable.
  2. Summarize at ABRs (area 1 range 10.10.0.0 255.255.0.0).
  3. Never run OSPF on user-facing ports (passive-interface default).
  4. Set router IDs manually and document them.
  5. Keep the topology shallow; OSPF is not a WAN design tool for 500 sites.

09 · BGP

BGP is the routing protocol of the Internet and of every large enterprise. It does not find the shortest path. It implements policy: who is allowed to reach what, through whom.

If OSPF asks "what is the fastest road?", BGP asks "which road am I contractually and politically allowed to use?"

Autonomous Systems

An AS is a network under one administrative control, identified by a number.

  • Public ASN: assigned by a registry (e.g. 13335 Cloudflare)
  • Private ASN: 64512–65534 (and 4200000000–4294967294 for 32-bit)
AS 65001 ---- AS 65002 ---- AS 65003
   eBGP          eBGP
  • eBGP — between different ASes. Default TTL 1, next hop changes.
  • iBGP — inside one AS. Full mesh required, next hop does not change by default.

Why iBGP needs full mesh or route reflectors

BGP does not re-advertise a route learned from one iBGP peer to another (loop prevention). So with n routers you need n(n−1)/2 sessions. At 20 routers that is 190 sessions.

Solutions:

  • Route reflector (RR) — one router reflects routes to clients.
  • Confederation — split the AS into sub-ASes.

In practice: route reflectors, always.

The BGP session

BGP runs over TCP port 179. It does not discover neighbors — you configure them.

Neighbor states:
Idle -> Connect -> Active -> OpenSent -> OpenConfirm -> Established
  • Active means "trying to connect" (counter-intuitive but correct).
  • Established means the session is up and routes are exchanging.
Cisco:  show bgp summary
        show bgp ipv4 unicast summary
        show bgp neighbors 10.1.1.2
FRR:    show bgp summary

Path attributes

A BGP route is a prefix plus a set of attributes.

Attribute Type Meaning
AS_PATH well-known mandatory sequence of ASes the route traversed
NEXT_HOP well-known mandatory where to send traffic
ORIGIN well-known mandatory IGP, EGP, or incomplete
LOCAL_PREF well-known discretionary preference inside the AS (higher wins)
MED optional hint to the neighbouring AS (lower wins)
WEIGHT Cisco proprietary local preference, highest wins, not advertised
COMMUNITY optional transitive tags for policy (e.g. no-export)
ATOMIC_AGGREGATE / AGGREGATOR optional summarization metadata

Best path selection

Cisco's order, simplified. Stop at the first difference.

  1. Highest weight (local only)
  2. Highest local preference
  3. Locally originated (network command, redistribute)
  4. Shortest AS_PATH
  5. Lowest origin (IGP < EGP < incomplete)
  6. Lowest MED
  7. eBGP over iBGP
  8. Lowest IGP metric to the next hop
  9. Oldest route (eBGP only)
  10. Lowest router ID
  11. Lowest neighbor address

Memorise the first six. That covers 95% of real questions.

The most important insight: BGP prefers the path with the fewest AS hops only at step 4. Local preference beats everything except weight — which is why enterprises control outbound traffic with local preference and inbound traffic with AS_PATH prepending or communities.

DNS — names to addresses

Resolution flow for www.example.com:

1. Host checks its cache, then /etc/hosts
2. Asks its configured resolver (recursive query)
3. Resolver checks cache; if miss, walks the tree:
   root -> .com -> example.com -> www.example.com   (iterative)
4. Returns the A/AAAA record, cached for the TTL
Record Meaning
A IPv4 address
AAAA IPv6 address
CNAME alias to another name
MX mail server

TXT SPF, DKIM, verification
PTR reverse lookup
SRV service location

TTL is the cache lifetime. Lowering TTL before a migration is standard practice; forgetting it is why "the change did not take effect" for hours.

Four steps, in order:

ACLs

An access list is an ordered list of permit/deny rules. First match wins. There is an implicit deny at the end.

Standard vs extended

12 · WAN, SD-WAN, and Cloud

The WAN is the part you do not own. That changes everything: cost, latency, and who you call when it breaks.

The old WAN

Technology What it was
Leased line dedicated circuit, expensive, fixed bandwidth
Frame Relay shared, committed rate, obsolete
ATM cell-based, obsolete
MPLS L3VPN provider-managed, any-to-any, QoS, still common

MPLS in one page

The provider builds a private network. Your sites connect to PE routers. The provider adds a label to each packet so core routers forward by label, not by IP lookup.

  • CE = customer edge, PE = provider edge, P = provider core
  • Labels stack; the outer label is the transport, the inner identifies the VPN
  • Traffic engineering and QoS come for free from the provider's SLAs
  • Expensive, slow to change (weeks to add a site)

You configure a plain IP link to the provider and run BGP or static routes with them. The MPLS magic is invisible to you.

The modern WAN: SD-WAN

Instead of one expensive private circuit, use several cheap ones (broadband, LTE, fiber) and let software choose the best path per application.

Feature What it does
Overlay builds tunnels (IPsec, WireGuard, proprietary) over any underlay
Application-aware routing voice goes over the low-latency link, backups over the cheap one
Central policy configure once, push to all sites
Zero-touch provisioning ship a box, it phones home and configures itself
Local internet breakout SaaS traffic goes straight out, not back to HQ

SASE extends this to security: cloud-delivered firewall, CASB, ZTNA, and SWG at the edge instead of a box in a data center.

Trade-off: SD-WAN is only as good as the underlay. If the broadband is congested, no policy can fix it.

DIA vs backhaul

Backhaul:  Branch -> HQ (inspect) -> Internet      slow, expensive, but centralized policy
DIA:       Branch -> Internet (local breakout)     fast, cheap, distributed policy

Most organisations now use hybrid: DIA for SaaS, backhaul/private for sensitive apps.

The mental model that transfers

  1. A VPC/VNet is a routing domain. Subnets are just address ranges inside it.
  2. Security groups are stateful and attached to resources. NACLs are stateless and attached to subnets.
  3. Cloud networks are default-deny for inbound, default-allow for outbound in most providers. That is the opposite of a naive on-prem firewall.
  4. Everything is software-defined. There is no spanning tree, no VLANs, no ARP storms.
  5. Routing is explicit. If a route table does not know a destination, the packet is dropped.

  • Use BGP for dynamic routing between on-prem and cloud.
  • Never overlap address space. Cloud VPCs make overlap painful and expensive to fix.
  • Two paths minimum, different providers if possible.
  • Put a firewall or inspection VPC between the edge and workloads.

13 · Troubleshooting Like an Engineer

This is the chapter that gets you hired. Anyone can configure a lab. Not everyone can find a problem at 2 a.m. without breaking it further.

The method

Never troubleshoot by trying random things. Use a loop.

1. Define the problem precisely
2. Gather facts
3. Form a hypothesis
4. Test the hypothesis
5. Fix, verify, document
   (if wrong, go back to 3 with new facts)

1. Define the problem

"The network is down" is not a problem statement. Ask:

  • Who is affected? One user, one floor, one site, everyone?
  • What exactly fails? DNS, a specific app, all traffic?
  • When did it start? What changed recently?
  • Is it constant or intermittent?

"What changed?" solves more tickets than any command.

2. Gather facts

Layer Fact Tool
L1 link up? errors? ip link, ethtool, show interface
L2 MAC learned? VLAN? ip neigh, bridge fdb, show mac address-table
L3 route exists? ip route, show ip route, traceroute
L4 port open? ss -tulpn, nc -vz, ACL counters
L7 app responds? curl -v, dig, logs

3. Form a hypothesis

A hypothesis is testable: "The DHCP relay is missing on VLAN 30, so hosts on VLAN 30 get link-local addresses."

Not testable: "It's probably the firewall."

4. Test it

One change at a time. If you change two things, you learn nothing.

5. Fix, verify, document

Verification means the user confirms it works, not "it pings now". Documentation means the next person (probably you at 3 a.m.) can find it.

Capture workflow

  1. Decide the capture point. The right question: "where can I see both directions?"
  2. Use a filter, not a 2 GB file. host 10.1.1.5 and port 443
  3. Reproduce the problem once.
  4. Stop and check counts: SYN sent? SYN-ACK returned? Retransmissions?
  5. Open in Wireshark, apply a display filter.

Useful Wireshark filters:

tcp.flags.syn == 1 && tcp.flags.ack == 0     # connection attempts
tcp.analysis.retransmission                  # retransmits
icmp.type == 3                               # unreachable
dns.flags.response == 0                      # DNS queries
tls.handshake.type == 1                      # client hello
arp                                          # ARP

Expert Information (Analyze → Expert Information) surfaces retransmissions, resets, and malformed packets without reading every packet.

When you hand off, give:

  2. up/up on an interface — does that prove routing works?
  3. Why is ping alone a weak test?
  4. What does a capture showing SYN with no SYN-ACK mean?

Answers
  1. "What changed?" — followed by scope (who/what is affected).
  2. No. It only proves Layers 1 and 2 are healthy.
  3. ICMP is often filtered or rate-limited; success does not prove the application path works.
  4. The packet reached the capture point but no reply came back (or the reply took another path/filter).
  5. On both sides of the firewall, so you can see what entered and what came out.

14 · Automation and Programmability

Every network engineer hired after 2020 is expected to automate. Not because it is trendy, but because a 500-device network cannot be configured by hand without errors.

Why automate

Manual Automated
500 devices × 20 min = 166 hours one script, 10 minutes
typos, missed devices, drift consistent, repeatable
knowledge in one person's head knowledge in Git
change window = all night change window = one hour

The goal is not "replace engineers". It is to stop wasting engineers on copy-paste.

Data formats

YAML

switches:
  - name: sw1
    mgmt: 10.0.0.11
    vlans: [10, 20, 30]
  - name: sw2
    mgmt: 10.0.0.12
    vlans: [10, 20]

JSON

{"switches": [{"name": "sw1", "mgmt": "10.0.0.11", "vlans": [10, 20, 30]}]}

YAML is for humans, JSON for machines. Both map to the same structures: dicts, lists, strings, numbers, booleans.

YANG is the data model — a schema describing what a device can be configured with. This is the "structured data" alternative to screen-scraping CLI output.

Python for network engineers

You need very little Python. This is the whole starting set:

# variables and strings
host = "10.0.0.1"
port = 22
print(f"connecting to {host}:{port}")

# lists and dicts
vlans = [10, 20, 30]
device = {"name": "sw1", "mgmt": "10.0.0.11"}

# loops
for vlan in vlans:
    print(f"vlan {vlan}")

# conditionals
if "mgmt" in device:
    print(device["mgmt"])

# files
with open("inventory.txt") as f:
    for line in f:
        print(line.strip())

# functions
def backup(host):
    return f"backup-{host}.cfg"

# error handling
try:
    do_something()
except Exception as exc:
    print(f"failed: {exc}")

Example: idempotent backup

import subprocess, datetime, pathlib

stamp = datetime.datetime.now().strftime("%Y%m%d-%H%M%S")
out = pathlib.Path("backups") / stamp
out.mkdir(parents=True, exist_ok=True)

for host in ["10.0.0.11", "10.0.0.12"]:
    cfg = subprocess.run(
        ["ssh", host, "show running-config"],
        capture_output=True, text=True, check=True,
    ).stdout
    (out / f"{host}.cfg").write_text(cfg)

Idempotent means: running it twice does not break anything.

Git

Non-negotiable. Your configs and scripts go in Git.

git init
git add .
git commit -m "add ospf lab"
git log --oneline
git diff

Why it matters: every change is attributable, reversible, and reviewable. A network engineer without Git is a network engineer who cannot answer "what changed?".

Safe automation rules

  1. Dry run first. Print what would change before changing it.
  2. One device at a time until the script is proven.
  3. Back up before deploy. Always.
  4. Verify after deploy. Compare the intended state to the actual state.
  5. Blast radius. Never run a loop over all devices on the first attempt.
  6. Rate limit. SSH sessions are cheap; device CPUs are not.
  7. Log everything. Who ran what, on which device, at what time.

What to learn next

  • Terraform for cloud/network infrastructure
  • Streaming telemetry (gNMI) instead of polling
  • CI/CD for network changes (GitHub Actions + tests)
  • Batfish to verify configs before deployment
  • Containerlab to test changes before touching production

Chapter check

  1. Why is YAML preferred for human-written config data?
  2. What is the difference between NETCONF and RESTCONF?
  3. What does "idempotent" mean?
  4. Why is Git essential for network automation?
  5. What is the first thing a deploy script should do?
Answers
  1. It is more readable (indentation, comments, fewer brackets) and maps cleanly to dicts and lists.
  2. Both use YANG models; NETCONF runs over SSH and is transaction-oriented, RESTCONF runs over HTTPS with REST semantics.
  3. Running it multiple times produces the same result — no duplicates, no drift.
  4. It gives history, attribution, review, and rollback for every change.
  5. Back up the current config (and print a dry run of what it intends to change).

15 · Labs

Fifteen labs, in order. Each one has a goal, a tool, and a proof — the thing you show someone to prove you did it.

Do not skip the proof. A lab you cannot demonstrate is a lab you did not learn.

Lab 01 — Two hosts, one switch

  • Goal: ping between two PCs on the same VLAN; read the MAC table.
  • Tool: Packet Tracer
  • Proof: show mac address-table output + explanation of why each MAC is on that port.

Lab 02 — ARP and the gateway

  • Goal: see ARP for the gateway when pinging a remote host.
  • Tool: Packet Tracer simulation mode + Wireshark
  • Proof: capture showing ARP request for the gateway, not for the destination.

Lab 03 — Subnetting drill

  • Goal: 50 random addresses, 100% correct.
  • Tool: pen and paper, then ipcalc
  • Proof: a sheet of worked answers with zero corrections.

Lab 04 — VLANs and trunks

  • Goal: two VLANs, one trunk, inter-VLAN routing with router-on-a-stick.
  • Tool: Packet Tracer
  • Proof: topology + show vlan brief + show interfaces trunk + successful cross-VLAN ping.

Lab 05 — Break the trunk

  • Goal: remove a VLAN from the allowed list and document the symptom.
  • Tool: Packet Tracer
  • Proof: a short table: what you broke, what you saw, how you fixed it.

Lab 06 — STP

  • Goal: three switches in a triangle; find the root, the root ports, the blocked port.
  • Tool: Packet Tracer
  • Proof: show spanning-tree from all three + a diagram of port roles.

Lab 07 — OSPF with three routers

  • Goal: full adjacency, loopbacks reachable, convergence under 10 s.
  • Tool: containerlab + netlab + FRR
  • Proof: show ip ospf neighbor, show ip route ospf, convergence timing.

Lab 08 — Break OSPF

  • Goal: cause and diagnose three failures: area mismatch, MTU mismatch, passive interface.
  • Tool: FRR
  • Proof: for each: the symptom, the state you saw, the fix.

Lab 09 — BGP between two ASes

  • Goal: eBGP session up, loopback advertised, AS_PATH visible.
  • Tool: FRR
  • Proof: show bgp summary + show bgp ipv4 unicast showing the path.

Lab 10 — BGP policy

  • Goal: change outbound preference with local preference, inbound with prepending.
  • Tool: FRR
  • Proof: before/after show bgp output with an explanation of which attribute decided it.

Lab 11 — ACLs and NAT

  • Goal: permit only HTTP/HTTPS out, block the rest, PAT the inside network.
  • Tool: Packet Tracer or FRR + iptables
  • Proof: policy working from two different source hosts + show ip nat translations.

Lab 12 — DHCP and DNS

  • Goal: a DHCP pool with relay, a local DNS record, a client that resolves it.
  • Tool: Linux containers or Packet Tracer server
  • Proof: dig output + DHCP lease table.

Lab 13 — Wireshark deep dive

  • Goal: explain six captures: ARP, ICMP TTL, OSPF hello, BGP open, DNS query, TCP retransmission.
  • Tool: Wireshark
  • Proof: notes/observations.md with "expected / saw / because" for each.

Lab 14 — Automation: config backup

  • Goal: back up every running lab device to timestamped files.
  • Tool: Python
  • Proof: script in Git + a backup directory + one paragraph on error handling.

Lab 15 — Automation: intent to config

  • Goal: YAML inventory → Jinja2 template → rendered config → deployed → verified.
  • Tool: Python + Jinja2 (+ Nornir if you want)
  • Proof: a commit showing the template, the rendered output, and the verification report.

D · Glossary

Every entry answers three questions: what it is, what it does, and why you should care. If a term has a chapter, the chapter explains it in context.

ACL rules, for example, are not just "permit/deny lists" — they are read top to bottom and stop at the first match, which is why a broad rule near the top makes every rule below it dead.

A

AAA — Authentication, Authorization, Accounting. The three questions asked of anyone who touches the network: who are you, what are you allowed to do, and what did you actually do. RADIUS and TACACS+ are the protocols that carry those answers.

ABR (Area Border Router) — An OSPF router with interfaces in two or more areas. It keeps a separate topology database for each area and advertises summaries between them, so routers inside one area never need to know another area's internals.

ACL (Access Control List) — An ordered list of permit and deny rules attached to an interface or a firewall. The device reads the rules from the top and stops at the first match, so the order is the policy: a broad permit placed too early makes every rule below it useless, and a missing final deny silently allows everything.

Administrative distance — The number a router uses to choose between routes to the same destination learned from different sources. Lower wins: connected 0, static 1, eBGP 20, OSPF 110, IS-IS 115, RIP 120, iBGP 200. It is the tiebreaker applied before metrics are compared.

Anycast — One address assigned to several servers in different locations. Routing delivers each client to the nearest one, which is how 8.8.8.8 and most CDNs work. If one node fails, traffic simply shifts to the others.

ARP (Address Resolution Protocol) — The protocol that finds the MAC address that owns an IPv4 address on the local link. A host broadcasts "who has 10.0.0.1?" and the owner replies with its MAC, which is then cached for a few minutes. Without ARP, a host knows where it wants to go but not which hardware to hand the frame to.

AS (Autonomous System) — A network under one administrative control, identified by an AS number. Routing between ASes is BGP's job; routing inside one AS is an IGP's job.

AS path — The BGP attribute listing every AS a route has passed through. It is both a loop check (seeing your own AS number means reject) and the usual tiebreaker: the shortest path wins unless policy says otherwise.

ASBR (AS Boundary Router) — An OSPF router that connects the OSPF domain to another routing domain and injects external routes into it. A router can be an ASBR and an ABR at the same time; the roles answer different questions.

Automation — Doing configuration and verification with code instead of typing into devices. The value is repeatability: the same input produces the same result, and one mistake is fixed once instead of on two hundred devices.

B

Bandwidth — The maximum rate a link can carry, measured in bits per second. It is a capacity, not a promise: what you actually get is throughput, which is always lower.

BFD (Bidirectional Forwarding Detection) — A lightweight protocol that sends tiny probes every few hundred milliseconds to detect a dead neighbour. Routing protocols use it so they can fail over in under a second instead of waiting for their own slow timers.

BGP (Border Gateway Protocol) — The routing protocol of the Internet. It exchanges reachability between autonomous systems and chooses paths by policy (which path you prefer) rather than by pure shortest path.

BPDU (Bridge Protocol Data Unit) — The message switches exchange to run Spanning Tree. It carries the bridge ID, root path cost, and port information that decide which ports stay forwarding and which get blocked.

BPDU guard — A switch feature that shuts a port down if it receives a BPDU. Applied to access ports, it stops a user from plugging in their own switch and quietly changing the topology.

Broadcast — A frame or packet addressed to every device on the local segment (MAC ff:ff:ff:ff:ff:ff, IPv4 255.255.255.255). Routers do not forward broadcasts, which is exactly what makes a broadcast domain end at the router.

Broadcast domain — Every device that receives a broadcast sent by any one of them. A whole switch is one broadcast domain unless VLANs split it.

C

CAM table (Content Addressable Memory) — A switch's map of MAC address to port. The switch learns an entry from every frame's source address and uses the table to send frames out only the correct port instead of flooding.

CIDR (Classless Inter-Domain Routing) — Writing a network as an address plus a prefix length, like 10.0.0.0/8. It replaced address classes, so the prefix defines the size — not the first octet.

Collision domain — The set of devices sharing one physical medium where frames can collide. A hub creates one large collision domain; a switch gives every port its own.

Community (BGP) — A tag attached to a BGP route, such as 65000:100. It has no built-in meaning — you define what it means and match it in route maps to apply policy at scale.

Control plane — The part of a device that decides where traffic should go: routing protocols, ARP, STP, and the tables they build. It is the "thinking" half of the router.

Convergence — How long the network takes to agree on a new topology after a change and stop sending traffic into a dead path. Fast convergence is a design goal, not a single feature.

CoS (Class of Service) — The 3-bit priority field inside an 802.1Q tag, used for QoS at Layer 2. It travels with the frame across trunks, so switches can honour priority without reading the IP header.

CPE (Customer Premises Equipment) — The device on the customer's side of a provider link, usually the router the ISP installs or hands over. It is where the provider's responsibility ends.

D

DAI (Dynamic ARP Inspection) — A switch feature that checks ARP packets against the DHCP snooping table and drops forged replies. It blocks ARP spoofing without installing anything on the hosts.

Data plane — The part of a device that actually moves packets: ASICs, the FIB, and the interfaces. Perfect routes in the control plane mean nothing if the data plane drops the traffic.

Default gateway — The router a host sends traffic to when the destination is not on its own subnet. If it is wrong or missing, local traffic still works and everything else fails — the classic "the network is down but only for me" symptom.

Default route — The route 0.0.0.0/0 (or ::/0), meaning "everything not matched more specifically goes here". It is the last resort in the routing table.

DHCP (Dynamic Host Configuration Protocol) — The protocol that gives hosts an address, mask, gateway, and DNS server automatically. It uses four messages: discover, offer, request, acknowledge.

DHCP snooping — A switch feature that marks ports trusted or untrusted and accepts DHCP offers only from trusted ports. It stops a rogue server from handing out a fake gateway.

DIA (Direct Internet Access) — Sending a branch's internet traffic straight out a local link instead of back through the data centre. It cuts latency and WAN cost, but moves the security controls to the branch.

DMZ (Demilitarized Zone) — A segment for services that must be reachable from the internet, kept separate from the internal network. If the web server is compromised, the attacker is still outside the inside.

DNS (Domain Name System) — The system that turns names into addresses. Almost every "the internet is down" ticket is really DNS, because everything else depends on it.

DR/BDR (Designated Router / Backup DR) — The two routers elected on an OSPF broadcast segment to be the only ones forming full adjacencies and generating LSAs for that segment. It keeps the number of adjacencies from growing quadratically as routers are added.

DSCP (Differentiated Services Code Point) — The 6-bit field in the IP header that marks a packet's QoS class. Edge devices set it, interior devices trust or rewrite it, and every hop uses it to choose a queue.

Dual stack — Running IPv4 and IPv6 on the same interface at the same time. It is the normal migration method because there is no flag day when the Internet switches over.

Duplex — Whether a link can send and receive at the same time (full) or only one direction at a time (half). A duplex mismatch causes collisions, retransmissions, and terrible throughput on a link that otherwise looks healthy.

E

eBGP — BGP running between routers in different autonomous systems. It is how networks exchange routes with each other, and it is the protocol that builds the Internet's routing table.

EIGRP (Enhanced Interior Gateway Routing Protocol) — Cisco's advanced distance-vector IGP. It converges quickly and summarizes easily, but it is effectively Cisco-only, which limits mixed-vendor designs.

Encapsulation — Wrapping data in the header of the layer below: a segment gets an IP header, the packet gets a frame header, and the frame becomes bits on the wire. Decapsulation is the reverse process on receipt.

EUI-64 — The 64-bit interface ID built from a 48-bit MAC by flipping the universal/local bit and inserting ff:fe in the middle. SLAAC uses it to build an address with no DHCP server.

EVPN (Ethernet VPN) — A BGP-based control plane for Layer-2 and Layer-3 overlays, usually paired with VXLAN. It replaces flood-and-learn with a real routing protocol, which is why large data centres use it.

F

FHRP (First Hop Redundancy Protocol) — A family (HSRP, VRRP, GLBP) that gives hosts one virtual gateway address served by two or more routers. If the active router dies, the standby takes over the address and the hosts never notice.

FIB (Forwarding Information Base) — The data-plane copy of the routing table, optimized for fast lookups. The control plane computes it; the ASIC reads it for every packet.

Floating static route — A static route configured with a worse administrative distance than the primary route, so it stays hidden until the primary disappears. It is a cheap backup path with no protocol overhead.

FRR (FRRouting) — An open-source routing suite that runs OSPF, BGP, IS-IS, and more on Linux. It is what the free labs in this book use instead of vendor images.

G

gNMI — A gRPC-based protocol for reading and changing device state, including streaming telemetry. It is the modern alternative to polling devices with SNMP or scraping the CLI.

GRE (Generic Routing Encapsulation) — A simple tunnelling protocol that wraps one protocol inside another. It can carry multicast and routing protocols, which IPsec alone cannot, but it adds no encryption by itself.

H

HSRP (Hot Standby Router Protocol) — Cisco's first-hop redundancy protocol. Routers share a virtual IP and MAC address; one is active, the other stands by and takes over if the active one stops answering.

I

iBGP — BGP running between routers in the same autonomous system. It carries external routes inside the AS and needs either a full mesh of sessions or route reflectors.

ICMP (Internet Control Message Protocol) — IP's signalling protocol. It carries errors such as "destination unreachable" and "time exceeded", plus the echo request/reply that ping uses. It carries no user data.

IGP (Interior Gateway Protocol) — Any routing protocol that works inside one autonomous system: OSPF, IS-IS, EIGRP, RIP. It finds the best path within your network, which is the opposite job to BGP.

IPAM (IP Address Management) — Keeping track of which addresses and prefixes exist and who owns them. Without it, duplicate addresses and exhausted pools are discovered by outage instead of by a report.

IPsec — A suite that encrypts and authenticates IP traffic. It has two parts: IKE negotiates keys and parameters, while ESP (or AH) protects the actual packets.

IS-IS (Intermediate System to Intermediate System) — A link-state IGP that runs directly on Layer 2 rather than inside IP. It scales very well and is common in ISP and provider cores.

ISP (Internet Service Provider) — The company that sells connectivity to the rest of the Internet.

J

Jitter — Variation in delay between packets. Voice and video care about jitter more than raw latency: a steady 150 ms sounds fine, but 20 ms ± 80 ms does not.

L

LACP (Link Aggregation Control Protocol) — The IEEE standard (802.3ad) for bundling several links into one logical link. It negotiates with the far end, so a half-configured bundle cannot silently create a loop.

Latency — The time a packet takes to travel from source to destination, measured in milliseconds. Distance, queueing, and serialization all add to it.

Link-state — A class of routing protocol where every router builds a complete map of the topology and runs shortest path over it. OSPF and IS-IS are link-state; they converge quickly and scale well.

Local preference — A BGP attribute used inside an AS to choose the outbound path. Highest wins, and it is exchanged only between iBGP peers — it never crosses an AS boundary.

Longest prefix match — The rule that a router forwards by the most specific route, not the first one configured. A /24 always beats a /16 for the same destination.

LSA (Link State Advertisement) — OSPF's unit of topology information. Routers flood LSAs until every router in the area holds the same database, and then each runs shortest path on it.

M

MAC address — The 48-bit hardware address of an interface, used only within one link. It is not routable, and it changes at every hop as frames are rebuilt.

MED (Multi-Exit Discriminator) — A BGP attribute that hints which entry point into an AS is preferred. Lower is better, and it is normally compared only between the same two neighbours.

Metric — The number a routing protocol assigns to a path to rank it. Lower is better, but the meaning differs by protocol: OSPF cost, RIP hop count, EIGRP composite.

MPLS (Multiprotocol Label Switching) — Provider forwarding that attaches a short label to each packet and switches on the label instead of doing an IP lookup at every hop. It is the basis of many carrier VPNs and traffic-engineering designs.

MSS (Maximum Segment Size) — The largest TCP payload a host will accept, usually MTU minus 40 bytes of IP and TCP headers. If a tunnel lowers the MTU, MSS clamping keeps TCP from overrunning it.

MTU (Maximum Transmission Unit) — The largest payload an interface will send; 1500 bytes on standard Ethernet. A path with a smaller MTU silently drops large packets unless PMTUD or MSS clamping deals with it.

Multicast — One sender, many receivers, using a group address. Hosts join a group and the network delivers only to links that have members. IPv4 uses 224.0.0.0/4; IPv6 uses ff00::/8.

N

NAT (Network Address Translation) — Rewriting addresses at a boundary, usually private to public. PAT, also called NAT overload, rewrites the source port too so many hosts can share one public address.

NDP (Neighbor Discovery Protocol) — IPv6's combined replacement for ARP, router discovery, and redirects. It runs over ICMPv6 and also performs duplicate address detection.

NETCONF — A protocol for configuring devices with structured data over SSH. It is transactional: you send a change, the device validates and applies it — or rejects the whole thing.

Next hop — The next device a packet is handed to on the way to its destination. The destination may be far away; the next hop is always exactly one hop away.

NOC (Network Operations Center) — The team and the room where monitoring, alerting, and incident response happen. Their runbooks matter as much as their dashboards.

NTP (Network Time Protocol) — The protocol that keeps clocks synchronized. Log correlation, certificates, and any real troubleshooting all depend on correct time.

O

OSPF (Open Shortest Path First) — A link-state IGP that floods LSAs, builds a topology map per area, and runs Dijkstra to find shortest paths. It is the most common interior protocol in enterprise networks.

Overlay — A virtual network built on top of a physical underlay, usually with tunnels. VXLAN, IPsec, and SD-WAN are overlays: they hide the underlay's details from the tenants.

P

Packet — The Layer-3 unit of data: an IP header plus payload. Frame is Layer 2, segment is Layer 4, packet is Layer 3.

PAT (Port Address Translation) — NAT that also rewrites the port, letting many internal hosts share one public address. It is what a home router does.

PBR (Policy-Based Routing) — Forwarding decisions based on something other than the destination, such as source address, protocol, or DSCP marking.

PDU (Protocol Data Unit) — The data unit at a given layer: frame at Layer 2, packet at Layer 3, segment at Layer 4.

Peering — Two networks exchanging traffic directly, usually without payment. It is a business relationship expressed as BGP configuration.

Ping — The tool that sends ICMP echo requests and measures the replies. Success proves the path and the return path work; failure does not tell you where it broke.

PoE (Power over Ethernet) — Sending power over the LAN cable with the data, so access points and cameras need no separate supply. Standards run from 802.3af (15.4 W) to 802.3bt (90 W).

Prefix — The network portion of an address, written with its length: 10.1.0.0/16. The prefix length is the number of leading bits that identify the network.

Prefix list — A filter that matches routes by prefix and length. For that specific job it is faster and harder to misconfigure than an access list inside a route map.

Q

QoS (Quality of Service) — Classifying, marking, and scheduling traffic so important packets are served first when a link is congested. It cannot create bandwidth; it decides who suffers when there is not enough.

Queue — A buffer where packets wait for an interface. Queueing is the mechanism behind QoS: which queue is served next is what "priority" actually means.

R

RADIUS — The protocol that centralizes authentication for 802.1X, VPN, and admin logins. The switch or router asks the RADIUS server whether the credentials are good.

Redistribution — Taking routes learned by one routing protocol and injecting them into another. It is where most routing loops and suboptimal paths are born, so it needs filtering and careful metrics.

Route map — A named list of match/set clauses applied to routes or packets. match selects which items are affected; set changes them.

Route reflector — An iBGP router that relays routes to its clients, replacing the full mesh that iBGP otherwise requires. It is the standard way to scale BGP inside an AS.

Route table — The list of destinations a device knows and where it will send traffic for each one.

Router — A device that forwards packets between networks using Layer-3 addresses. It breaks up broadcast domains and marks where one subnet ends and the next begins.

Routing policy — The rules that decide which routes are accepted, preferred, and advertised. In BGP, policy usually matters more than the protocol's own path calculation.

RPKI (Resource Public Key Infrastructure) — A system that cryptographically certifies which AS is allowed to originate which prefixes. It prevents a whole class of BGP hijacks.

RSTP (Rapid Spanning Tree Protocol) — The 802.1w version of STP, converging in under a second instead of tens of seconds. It is the default on modern switches.

S

SD-WAN (Software-Defined WAN) — A policy-driven overlay that spreads traffic across several WAN links according to application needs. It replaces static routing over expensive circuits with measured, per-application path selection.

Segment — The Layer-4 unit: a TCP or UDP header plus payload. The word is also used loosely to mean a piece of a network, so context matters.

Shaping — Delaying packets to keep the rate at or below a limit. Unlike policing, it does not drop traffic; it smooths bursts by buffering them.

SLAAC (Stateless Address Autoconfiguration) — IPv6 hosts build their own address from the prefix a router advertises plus an interface ID. No DHCP server is involved.

SNMP (Simple Network Management Protocol) — The classic protocol for polling counters and receiving traps from devices. Streaming telemetry is replacing it, but it is still everywhere.

Spanning tree — The protocol that keeps a switched network loop-free by electing a root bridge and blocking redundant ports. Without it, one loop saturates a network in seconds.

Static route — A route configured by hand. It does not adapt to failures unless it is paired with something like BFD or a floating backup.

STP (Spanning Tree Protocol) — The IEEE 802.1D protocol that prevents Layer-2 loops. It blocks ports so that exactly one active path exists between any two points.

Subnet — A slice of a larger network, defined by a prefix. Subnetting is the act of choosing where to split the host bits.

Subnet mask — The 32-bit value with 1s in the network bits and 0s in the host bits. The device ANDs it with an address to find the network.

Summarization — Advertising one short prefix instead of many longer ones. It shrinks routing tables, but it hides detail, so a flapping component can still affect the whole summary.

SVI (Switch Virtual Interface) — A Layer-3 interface that represents a VLAN on a switch, used for management or for routing between VLANs.

Switch — A device that forwards frames within a network using MAC addresses. It learns which MAC is on which port and floods only what it has to.

Syslog — The standard for shipping log messages to a central server. It is the first place to look when something changed at 2 a.m.

T

TACACS+ — A Cisco-originated AAA protocol that separates authentication, authorization, and accounting and encrypts the whole payload. It is common for device administration rather than user access.

TCP (Transmission Control Protocol) — A connection-oriented transport that guarantees ordered delivery, retransmits lost data, and adjusts its rate to the network. Web, SSH, and most control traffic use it.

Throughput — The rate actually achieved, as opposed to the link's capacity. Overhead, loss, and latency keep it below the advertised bandwidth.

TLS (Transport Layer Security) — The protocol that encrypts and authenticates application traffic; HTTPS is HTTP inside TLS. It replaced SSL.

Traceroute — A tool that reveals the path by sending packets with increasing TTL values and collecting the "time exceeded" replies. Missing hops usually mean filtering, not a broken path.

Transit — Carrying traffic between two other networks for a fee. It is the opposite of peering.

Trunk — A link that carries several VLANs at once, tagging each frame with its VLAN ID (802.1Q). Access ports carry one untagged VLAN; a trunk is what connects two switches, or a switch to a router that needs to route between VLANs.

TTL (Time to Live) — A counter in the IP header that decreases at every router. At zero the packet is dropped — which stops loops and is what makes traceroute possible.

Tunnel — An encapsulation that makes a packet look like it belongs to another network. VPNs and overlays are built from tunnels.

U

UDP (User Datagram Protocol) — A connectionless transport with no retransmission and no ordering. DNS, DHCP, and voice use it because a late packet is worse than a lost one.

ULA (Unique Local Address) — IPv6 private space, fc00::/7. It is not routable on the internet and plays the role RFC 1918 plays for IPv4.

Unicast — One sender, one receiver, addressed to a single host. It is the normal case for almost all traffic, and it is what a switch forwards using its CAM table instead of flooding.

Underlay — The physical network that carries an overlay's tunnels. If the underlay is unstable, the overlay inherits every problem.

uRPF (Unicast Reverse Path Forwarding) — An anti-spoofing check: accept a packet only if the source address is reachable through the interface it arrived on.

V

VLAN (Virtual LAN) — A logical broadcast domain inside a switch. Ports in different VLANs cannot talk at Layer 2 even when they are on the same physical switch.

VLSM (Variable Length Subnet Mask) — Using different prefix lengths inside one address block so every subnet is sized to its actual need instead of all being equal.

VRF (Virtual Routing and Forwarding) — Several independent routing tables on one device. It lets overlapping addresses coexist, which is the basis of MPLS VPNs and multi-tenant designs.

VRRP (Virtual Router Redundancy Protocol) — The open-standard first-hop redundancy protocol. It does the job of HSRP without being vendor-specific.

VXLAN (Virtual Extensible LAN) — A tunnel that carries Layer-2 frames over a Layer-3 network, identified by a 24-bit VNI. It allows far more segments than 802.1Q's 4094 VLANs.

W

WAN (Wide Area Network) — The links that connect sites across a provider's infrastructure, as opposed to the LAN inside one site.

Wildcard mask — The inverse of a subnet mask, used in ACLs and OSPF network statements. A 0 bit means "must match"; a 1 bit means "don't care".

Wireshark — The packet analyzer. It is the only tool that shows what actually crossed the wire, which is why it settles most arguments.

Y

YANG — The data modelling language that describes a device's configuration and state as a structured tree. NETCONF and gNMI both carry YANG-modelled data.

Z

Zero trust — A security model that authenticates and authorizes every request instead of trusting anything because it is "inside". The network becomes transport, not a trust boundary.
